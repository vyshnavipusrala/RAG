## Chunk Enhancement Techniques in RAG

**Chunk enhancement** = Improving chunks before storing them in the vector database to improve retrieval quality.

1. **Contextual Chunking**

   * Adds surrounding context to make chunks more understandable.

2. **Contextual Retrieval**

   * Adds document title, section, or background information to each chunk.

3. **Metadata Enrichment**

   * Adds metadata like **document name, page, section, date, and department**.

4. **Chunk Summarization**

   * Creates a short summary of each chunk for better semantic matching.

5. **Hypothetical Questions**

   * Generates possible questions that the chunk can answer and uses them for retrieval.

6. **Parent-Child Chunking**

   * Uses small child chunks for precise retrieval and larger parent chunks to provide context.

7. **Chunk Overlap**

   * Overlaps neighboring chunks to preserve context across boundaries.
  
## Common Chunking Methods in RAG

**Chunking** = Splitting large documents into smaller pieces so they can be efficiently embedded and retrieved.

1. **Fixed-Size Chunking**

   * Splits text into chunks of a fixed number of tokens/characters.
   * Simple and fast.
   * Example: 500 tokens with 50-token overlap.

2. **Recursive Character Chunking**

   * Splits text using separators such as paragraphs, sentences, and spaces.
   * Tries to keep related text together.
   * Commonly used in RAG.

3. **Sentence-Based Chunking**

   * Splits documents based on complete sentences.
   * Helps preserve sentence-level meaning.

4. **Paragraph-Based Chunking**

   * Splits text according to paragraphs.
   * Useful when each paragraph contains a complete idea.

5. **Semantic Chunking**

   * Splits text based on **meaning/topic changes** rather than fixed size.
   * Keeps semantically related information together.

6. **Document/Structure-Based Chunking**

   * Uses document structure such as **headings, sections, chapters, and subsections**.
   * Useful for structured documents and technical documentation.

7. **Parent-Child Chunking**

   * Creates smaller child chunks for precise retrieval and larger parent chunks for context.
   * Retrieve child → provide parent context to the LLM.

### Remember:

> **Fixed-size → Simple**
> **Recursive → Flexible**
> **Sentence/Paragraph → Natural boundaries**
> **Semantic → Meaning-based**
> **Structure-based → Document organization**
> **Parent-child → Precision + context**


8. **Semantic Chunking**

   * Splits text based on **meaning and topic** rather than only fixed token size.

### Remember:

> **Better chunks + better context → better retrieval → better RAG answers.**

## Criteria to Choose a Chunking Method in RAG

The chunking method should be selected based on the **document type, content structure, query type, and RAG requirements**.

1. **Document Type**

   * PDFs, web pages, code, tables, FAQs, and legal documents may need different strategies.

2. **Document Structure**

   * If documents have clear headings/sections → use **structure-based chunking**.
   * For unstructured text → **recursive or semantic chunking** may work better.

3. **Query Type**

   * Simple factual queries → smaller chunks may be sufficient.
   * Complex questions → larger or parent-child chunks can preserve more context.

4. **Context Requirements**

   * If information spans multiple sentences/paragraphs → use **overlap or larger chunks**.

5. **Retrieval Precision**

   * Smaller chunks generally provide more precise retrieval.
   * Avoid chunks that are so small that they lose necessary context.

6. **Semantic Coherence**

   * Keep related information together.
   * **Semantic chunking** is useful when meaning is more important than fixed size.

7. **Latency and Cost**

   * More/smaller chunks increase the number of embeddings and retrieval operations.
   * Larger chunks increase the amount of context sent to the LLM.

8. **Evaluation**

   * Test different chunking strategies and compare:

     * **Context Precision**
     * **Context Recall**
     * **Answer Relevance**
     * **Faithfulness**
     * Latency and cost

### Remember:

> **Document type + Structure + Query type + Context needs + Retrieval quality + Cost/Latency → Choose the chunking method.**
